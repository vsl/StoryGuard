# BM25 Retrieval Baseline

## Experiment metadata

```text
experiment_id: 2026-08-24-bm25-gacha-baseline
status: accepted as fixed lexical baseline
strategy: Elasticsearch default BM25
candidate_k: 30
primary_split: held-out test
```

This report supersedes the initial three-document smoke measurement for quality
comparison. The smoke run remains relevant only because it revealed that the
old dataset and single-chunk labels were not trustworthy enough for retrieval
decisions.

## Hypothesis and developer prediction

Elasticsearch BM25 should be strong when questions and evidence share exact
names or rare terms. It should be weaker when they express the same meaning with
different words.

The developer predicted that an exact query such as `Alex` should work well,
while `car` could miss a passage containing only `BMW`. BM25 is needed as both a
measurable baseline for embeddings and the lexical branch of later hybrid
retrieval.

## Retrieval configuration

- Elasticsearch: `8.19.19`;
- similarity: default BM25;
- query: `match` over chunk `text`;
- mandatory filters: `project_id` and `manuscript_version_id`;
- ranking: `_score` descending, then `chunk_id` ascending;
- candidate K: `30`;
- experiment index: disposable `storyguard-chunks-gacha-eval-v2`;
- production index: untouched `storyguard-chunks-v1`.

The disposable index is recreated for every run. This prevents production data
and deleted-document tombstones from changing index-wide BM25 statistics. Two
repeated isolated runs produced identical quality metrics.

## Chunking and relevance labels

```text
parser: v2
tokenizer: regex-v1
chunking: storyguard-700-900-v1
target/max/overlap: 700/900/100 tokens
parsed chunks: 2,108
qrels: 324
```

Ground truth is derived without trusting a supplied chunk ID:

```text
question
  -> exact chunk-must-contain evidence in its full book
  -> all same-book StoryGuard chunks containing the evidence
```

All 292 questions have non-empty question, answer, and evidence fields. Each
evidence span occurs exactly once in its selected full book and appears in at
least one StoryGuard chunk. There are 260 single-qrel questions and 32 questions
with two relevant overlapping chunks.

Automatic evidence containment is not treated as conclusive semantic judgment.
Hard failures expose question, answer, evidence, and Top-10 chunk previews for
manual inspection.

## Manual failure analysis

Question:

```text
How did Anne respond when Mrs. Barry did not acknowledge the correct spelling
of her name?
```

Gold answer and context:

```text
“Spelled with an E,” gasped Anne...
Mrs. Barry, not hearing or not comprehending...
```

The labeled chunk ranked 16. Manual review found that none of the Top-10 chunks
answered the question, while the labeled chunk clearly did. The developer
classified this as a genuine retrieval failure.

The discriminating meaning is paraphrased rather than repeated lexically:

```text
did not acknowledge       <-> not hearing or not comprehending
correct spelling          <-> Spelled with an E
```

Higher-ranked chunks shared common entity terms such as `Anne`, `Mrs. Barry`,
and `Diana` but described other scenes. The result supports the original
lexical-mismatch hypothesis and provides a concrete vector-retrieval test case.
It does not establish that vector retrieval will perform better.

## Superseded smoke result

The original `illuin-conteb/narrative-qa` smoke fixture contained 20 queries and
only three indexed documents. It reported Recall@1 `0.80`, MRR `0.875`, and
Recall@5+ `1.00`, but those values were not meaningful quality evidence. Its
single-chunk label penalized a directly relevant Mark/FCC chunk, demonstrating
incomplete ground truth. It must not be compared with current or future
retrieval candidates.

## Verification

- fixture generation reproduced the committed pinned manifest;
- backend suite: 20 tests passed, 7 unrelated opt-in integrations skipped;
- Elasticsearch retrieval integration: 4 tests passed;
- repeated isolated experiment runs produced identical Recall and MRR;
- experiment index was removed after the run;
- project/version scope checks found no cross-project or old-version leakage;
- no LLM, embedding model, reranker, paid API, or LangSmith trace was involved.

## Decision

Accept this Gacha BM25 run as the fixed lexical baseline. Do not tune BM25 before
the vector comparison. Vector, hybrid, and hybrid-plus-reranker experiments must
reuse the exact corpus, queries, qrels, split assignments, chunking configuration,
and fingerprints above.

No retrieval candidate has been promoted over BM25. That decision belongs to
the later experiments after metric and failure analysis.

## Open risks

- Evidence containment can still create false-positive or false-negative
  semantic labels; manually inspect important disagreements.
- Ten classic English-language books do not represent every StoryGuard
  manuscript style or language.
- The dev/test split is book-level but small.
- Non-commercial licensing is acceptable for the current pet project, not an
  unrestricted commercial dataset choice.
